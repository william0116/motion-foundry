# 开源发布检查表

这是维护者发布门禁，不是已经完成的安全认证或发布记录。每次发布应在变更说明中记录实际检查结果与提交 SHA。

## 首次公开源码

- [ ] 确认 README 中的能力与当前提交一致，图片、文档链接和安装命令可用。
- [ ] 确认项目 MIT 许可、版权归属和第三方声明；核验图片、字体、图标、音频和依赖的分发权。
- [ ] 审查**全部拟公开分支、标签和 Git 历史**，不仅扫描最新工作区；确认没有凭证、客户信息、内部路径、私有资源标识或不适合公开的协作记录。
- [ ] 注意：删除最新文件不会删除历史副本。若历史不宜公开，可在明确授权后创建仅含审查通过文件的新公开仓库；不要自行改写现有远程历史或直接执行镜像推送。
- [ ] 如发现曾提交有效凭证，先撤销／轮换，不能仅删除文件后继续发布。
- [ ] 确认公开平台、仓库地址、维护者身份与私密安全报告渠道，再补充对应入口；不要使用虚构联系方式。
- [ ] 检查 README 克隆说明、仓库描述、默认分支与可见性；必要时配置分支保护和 CI。
- [ ] 用全新目录、无本机额外依赖的环境按 README 安装与测试，不能依赖开发者绝对路径。

## 每次发布

- [ ] `npm ci` 安装成功，锁文件与依赖声明一致。
- [ ] `npm run check`、`npm test`、`npm run test:browser` 通过，记录浏览器版本及跳过项。
- [ ] 视觉变更完成人工检查；确认桌面与小屏操作路径、长文本、透明边缘和下载结果。
- [ ] 导出变化使用独立解码器或目标剪辑软件验收，不只看浏览器预览。
- [ ] 记录变更范围、已知问题、提交 SHA 和上一可用版本。
- [ ] 获得发布确认后才推进 `prod`，仅部署完整 `dist/`，不推送私有媒体或课程材料。
- [ ] 部署后验证缓存、静态资源版本、首页和实际导出；准备可执行的回滚路径。

## 不应作为宣传材料的内容

不要把开发过程的对话、工具执行记录、内部协作配置或尚未验证的探索方向当成功能介绍。测试通过只证明对应断言通过，不应改写成“完全兼容所有浏览器”“等同 AE”或“自动完成视频剪辑”。
